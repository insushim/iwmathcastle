## 0. 현황 진단 (실측)

| 항목 | 현재 상태 |
|---|---|
| 코드 | 바닐라 JS + 듀얼 캔버스 + DOM 이펙트 하이브리드, 총 45,163줄 |
| 문제 | 20,776개 (3~6학년 각 ~5,100개) — **학년 위반·오류 다수 발견** |
| 콘텐츠 | 타워 23종, 몬스터 34종(보스급 7), 마법 5종, 엘리트 시스템, 업적, 콤보 |
| 에셋 | **이미지 파일 0개** — 100% 절차적 캔버스 드로잉 (monsterRenderer 4,984줄, towerRenderer 3,321줄) |
| 배포 | Cloudflare Workers + D1(랭킹), Firebase |

### 진단 A. 학년 정합성 위반 (랜덤 샘플 실측)

| 학년 | 위반 사례 | 실제 해당 학년 |
|---|---|---|
| 3 | `9839원 + 8169원` (네 자리 덧셈) | 3학년은 세 자리 덧셈·뺄셈까지 |
| 4 | `38와 29의 최대공약수는?`, `49와 73의 최소공배수는?` | 약수·배수는 **5학년** |
| 4 | `110 ÷ 7 × 22` — **나누어떨어지지 않음 (오류 문제)** | 혼합계산 자체도 5학년 |
| 5 | `직육면체 부피 (cm³)`, `가장 간단한 비`, `40% 할인` | 부피·비·백분율은 **6학년** |
| 6 | `6개 중 2개를 뽑을 확률` | 확률 계산은 **중1** |
| 6 | `4 × 8 = 32, 맞으면 O 틀리면 X` | 2학년 수준 (너무 쉬움) |
| 전체 | 조사 오류: `38와`, `205팩와 184팩를`, `15과 18` | 국어 오류 |

### 진단 B. 웨일북(저사양 크롬북) 성능 리스크

1. **DOM 이펙트 풀** — 마법 이펙트가 div + CSS 애니메이션으로 렌더 → 저사양에서 reflow/composite 병목
2. monsterRenderer에 `shadowBlur` 14곳 잔존 (프레임당 큰 비용)
3. 몬스터 최대 80마리 × 절차 드로잉 (오프스크린 캐시 부분 적용 상태)
4. DPR/저사양 감지 없음 — 웨일북은 dpr 1 강제 필요 (아트온 프로젝트 실측: dpr² 비용으로 프레임 471ms→29ms 개선 사례)
5. rAF 루프에 try/catch 없음 — 예외 1회로 렌더 영구 정지 위험 (아트온 실측 교훈)
6. problems.js 1MB가 초기 로드에 포함

### 진단 C. 학습 루프 약점

- 오답 시 정답 노출/풀이 없음 → 학습 효과 제한
- 틀린 문제 재출제(간격 반복) 없음
- 정답→화력 연결이 간접적 (골드만) → "잘 풀수록 강해진다" 체감 약함

## 4. 워크스트림 7개

### WS-1. 학년별 문제 재정비 ★사용자 지적 사항
1. **2022 개정 교육과정 학년별 연산 규칙표** 작성 (`docs/curriculum-map.md`)
   - 3학년: 세 자리 ±, (두 자리)×(한 자리), (두 자리)÷(한 자리) 나누어떨어짐, 분수 기초
   - 4학년: 큰 수, (세 자리)×(두 자리), (두·세 자리)÷(두 자리), 분수 동분모 ±, 소수 ±
   - 5학년: 혼합계산, 약수·배수(최대공약수·최소공배수), 이분모 분수 ±, 소수 ×, 다각형 둘레·넓이
   - 6학년: 분수·소수 ÷, 비와 비율·백분율, 직육면체 부피·겉넓이, 속력, 원의 넓이
2. **자동 검증기** `tools/problem-validator.mjs`: 전 문제 파싱 → 학년 규칙 위반·비정수 나눗셈·정답 재계산 불일치·조사 오류 전수 검출
3. 위반 문제는 **해당 학년 규칙으로 프로그램 재생성** (학년당 5,000+ 유지, 단원 커버리지 균형)
4. 조사 자동 교정 (와/과, 을/를, 이/가 — 받침 판정)
5. 학년별 파일 분할 (`problems/grade3.js` …) + 학년 선택 시 동적 import

### WS-6. 중독성 & 실제 학습 향상 ★사용자 지적 사항
1. **오답 학습 루프**: 오답 시 정답 + 한 줄 풀이 표시(3초) → 틀린 문제는 재출제 큐에 등록, 2~3웨이브 뒤 재등장 (간격 반복)
2. **정답 스트릭 = 마법 게이지**: 연속 정답이 마법 충전 가속 → "수학을 잘 풀수록 강해진다" 직결
3. 웨이브 종료 리포트: 정답률·연속 기록·이번 판 배운 유형 요약
4. 업적 확장 (학습 업적: "나눗셈 마스터" 등 단원별)
5. 게임 주스: 정답 시 화면 연출 강화(캔버스), 히트스톱, 데미지 넘버 (전부 성능 예산 내)
6. D1 랭킹에 학년별 리더보드 분리

### WS-7. 로직 점검 + 헤드리스 검증 인프라
1. **시뮬 코어 분리**: 웨이브·전투·경제 로직을 DOM 미참조 모듈로 추출 (main.js 3,775줄 분해) — 헤드리스 테스트 전제 조건
2. 헤드리스 시나리오 3종: 표준 플레이 / 풀 업그레이드 / 고의 패배 + 불변식(골드 음수·HP 초과·죽은 몬스터 잔존 금지)
3. 시각 QA: Puppeteer 캡처(CPU 래스터 강제) → 5축 분석 → 수정 루프 (최대 3회)
4. 게임 로직 버그 점검: 미믹·텔레포터·스플리터 등 특수 몬스터 엣지케이스, 타워 판매/변환 골드 정합

## 5. 실행 순서 & 게이트

```
Phase A (기반):    WS-7 시뮬 코어 분리 → WS-1 문제 재정비 (+검증기 게이트)
Phase B (병행):    WS-2 성능 최적화 ∥ WS-3 에셋 생성·적용
Phase C (콘텐츠):  WS-5 마법 확장 → WS-4 밸런스 프로브·조정
Phase D (마감):    WS-6 학습·중독성 → 통합 검증 (헤드리스 + 시각QA + 밸런스 프로브 재실행)
Phase E (출고):    Final Review Gate (3-Pass) → 성능 실측 보고 → 배포
```

각 Phase 종료 시 게이트: 콘솔 에러 0건 + 해당 DoD 항목 통과 + 회귀(이전 Phase DoD) 유지.
