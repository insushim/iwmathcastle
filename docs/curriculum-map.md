## 시간등급 (t) — 유형별 제한시간
| t | 유형 | 기본 시간 | 비고 |
|---|---|---|---|
| 1 | 한 줄 연산 | 20초 | 세로셈 한 번 |
| 2 | 복합 연산 | 35초 | 두 단계 이상 계산 |
| 3 | 도형·측정 공식 | 45초 | 공식 상기 + 계산 |
| 4 | 문장제 | 50초 | 독해 + 식 세우기 |

저학년(3~4학년)은 +5초 보정. 시간 초과 = 오답 처리(경감 페널티) + 풀이 힌트.

**v7: 여기에 문항 길이 비례 보정을 더한다.** 유형 상수만 쓰면 같은 t 안에서 길이가
2배 넘게 차이 나는 걸 못 잡는다(실측: 6-1 문장제 평균 43자 / 최장 66자, 둘 다 50초).
기준 30자를 넘는 만큼 읽기 시간을 준다 — 3~4학년 0.4초/자, 5~6학년 0.25초/자, 최대 +15초.
시간 초과는 "몰라서"가 아니라 "못 읽어서" 틀리게 만들 수 있고, 그건 학습 신호가 아니다.

**문항은 짧게 쓸 것.** 66자짜리 문장제는 740×300 폰에서 보기 4개를 화면 밖으로 밀어냈다.
`.math-modal`은 짧은 가로화면에서 세로 플렉스로 동작해 질문만 스크롤하고 보기는 항상
보이도록 고쳤지만(qa-learning ⑧이 감시), 애초에 길게 쓰지 않는 게 맞다.
> v7: 시간 초과가 `learnLoop.recordWrong`을 호출하지 않아 재출제 큐·오답노트·통계 어디에도
> 남지 않던 버그를 고쳤다. 이제 문서대로 오답으로 기록되고 힌트도 표시된다.

## 공통 품질 규칙
1. 나눗셈은 "나머지" 명시가 없으면 반드시 나누어떨어질 것
2. 정답은 생성 시 계산으로 확정 — 검증기가 독립 재계산으로 이중 확인
3. 조사(와/과, 을/를, 이/가, 은/는)는 받침 판정 함수로 자동 결정
4. 단위는 질문에, 정답은 순수 숫자로 (분수 답 `a/b`·비율 답 `a:b`·개념 판별형 제외)
5. 문제 문자열 학기 내 중복 금지
6. 답이 0 또는 음수인 문제 금지 (오답 생성기 호환)
7. 오답(d)은 **정확히 3개**. 4개 이상 담으면 main.js가 무작위로 3개만 뽑아 아래 8·9번 통제가 무너진다
8. 정답 위치는 런타임 셔플 — 검증기가 시뮬레이션으로 4지선다 각 25%±2% 게이트
9. **정답의 크기 순위도 균등해야 한다** (v7 신설, 아래 참조)

## 풀이 힌트 설계 (v8 · learnLoop.js)

오답 시 보여주는 한 줄 풀이는 **그 문제의 실제 숫자를 대입한 계산식**이어야 한다.
v7까지는 도형·문장제에서 "넓이 공식을 떠올려 보세요. 답: 42"처럼 정답 숫자만
재확인시켜 줬다(숫자 대입률 0%). 그건 학습이 아니라 정답 암기다.

두 가지 규칙:

1. **계산식은 검산을 통과해야 나간다.** 문장제는 문장마다 숫자 순서가 다르다
   ("191원짜리 6개를 사고 1313원을 내면" vs "3100원을 내고 700원짜리를 4개").
   순서를 하나로 가정하면 틀린다 — 실제로 895문항에 틀린 풀이가 나갔다.
   `verified(a, 후보식들)`이 정답과 맞아떨어지는 식만 고르고, 없으면 개념 힌트로 물러난다.
   **틀린 풀이를 보여줄 바에는 없는 게 낫다.**
2. **낱글자 키워드 매칭 금지.** `q.includes("분")`은 "분수"에 걸린다. 실제로
   "1/2와 1/6 중 더 큰 분수는?"에 "1시간 = 60분!"이라고 답하고 있었다(244문항).
   단위 힌트는 숫자+단위가 붙은 경우만 잡는다.
3. **정답이 분수·비율이면 계산식 힌트를 만들지 않는다.** "1/2"를 12로 읽으면
   우연히 12가 나오는 엉뚱한 식이 통과한다.

게이트: `node tools/qa-adaptive.mjs` — 숫자 대입률 ≥80%(현재 95.0%),
계산식 검산 오류 0(현재 12,101개 중 0), 무관한 단위 힌트 0, 분수 정답 계산식 0.

## 오답 선택지 설계 (v7 · distractors.js)

2026-07-27 감사에서 치명적 결함이 나왔다. 구버전 `makeDistractors`는 정답 기준
±1, ±2로 **대칭** 배치했다. 그 결과:

| 지표 | 구버전 | v7 |
|---|---|---|
| 정답이 "가운데 2개"에 들어갈 확률 | **91.2%** | 50.0% |
| 계산 없이 "가운데 찍기" 승률 | **45.6%** | 25.0% |
| 100%였던 골격 수 (나눗셈·최대공약수·비례식 등) | 11종 | 0종 |

`936 ÷ 39 = 24` → 오답이 `[25, 23, 26, 22]`, 즉 보기가 늘 네 개의 연속된 수이고
정답은 절대 최댓값·최솟값이 되지 않았다. **학습을 안 하는 쪽이 이득인 유인 구조**였다.

두 축으로 고친다:

1. **오답 내용 = 실제 오개념.** 자릿수 밀림(×10·÷10), 받아올림/받아내림 누락,
   자리마다 |큰수−작은수|, 연산 혼동(+↔×), 부분곱 누락, 몫↔나머지 바꿔쓰기,
   분모끼리 계산, 통분 안 함, 뒤집지 않고 곱하기, 넓이↔둘레·부피↔겉넓이 혼동,
   최대공약수↔최소공배수 혼동, 삼각형 넓이에서 ÷2 빠뜨림 등.
2. **오답 배치 = 정답 순위 강제 균등화.** 문항마다 목표 순위(0~3)를 주고,
   "지금까지 가장 적게 쓴 순위"를 다음 목표로 삼아 자기교정한다.

지켜야 할 것:
- **값이 정답과 같은 표기를 오답으로 쓰지 말 것.** `1/2`의 오답에 `4/8`을 넣으면
  수학적으로 정답이다(초판에서 실제로 발생). 분수 오답은 기약분수만 허용한다.
- **극단값 금지.** `615 + 152`의 오답에 `93480`(=615×152)을 넣으면 계산 없이 걸러진다.
  정답의 1/10.5 ~ 10.5배 밴드 안으로 제한한다.
- **자릿수 밀림 오답은 절반 문항에만.** 항상 넣으면 "자릿수가 다수파인 것 고르기"가
  25% → 33%로 올라간다. 문제 문자열 해시로 결정적으로 절반만 넣는다.
- 템플릿이 `d`를 직접 주는 경우(비·개념 판별형)도 **정확히 3개**여야 한다.

## 복습 시스템 (v7 · learnLoop.js)

감사에서 드러난 3가지 구조 결함을 고쳤다.

| 항목 | 구버전 실측 | v7 |
|---|---|---|
| 세션 내 재출제 간격 | 3 → 3 → 3 (7·15는 死코드) | 맞히면 3 → 7 → 15, 틀리면 3으로 복귀 |
| 오답노트 활용 | 50칸 중 앞 3칸 고정 → 23개 영구 미출제 | 예정일+라운드로빈, 최대 8문항 |
| 날짜 단위 반복 | 없음 (전부 같은 세션 몇 분 내) | 라이트너 1일 → 3일 → 7일 → 16일 → 졸업 |
| 누적 약점 추적 | 매 판 초기화 | `mathcastle:learnstats`에 유형별 누적 |

- `popDueReview`는 큐에서 **splice하지 않는다.** 빼버리면 채점 시 항목을 못 찾아
  간격 승급 분기에 영영 도달하지 못한다(구버전 버그의 직접 원인).
- 오답노트 스키마 v2: `{q,a,d,t, box, due, seen, ok, added, rr}`.
  v1(`{q,a,d,t}`)은 자동 마이그레이션되며, 이때 구 대칭 오답을 새 생성기로 갈아끼운다.
- 예정일이 같은 문항이 여럿이면 `rr`(라운드로빈 티켓)로 가장 오래 안 나온 것을 고른다.
  이게 없으면 배열 앞쪽 3개만 무한 반복된다(실측: 50개 중 47개 미출제).
