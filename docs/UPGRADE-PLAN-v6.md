## 2. [P0] 제한시간 차등화

30초 고정 폐지 → **문제 유형별 기본시간 + 학년 보정**:

| 유형 | 기본 |
|---|---|
| 한 줄 연산(덧뺄셈·구구단 수준) | 20초 |
| 복합 연산(두자리 곱셈, 혼합계산, 분수·소수 연산) | 35초 |
| 도형·측정 공식(넓이·부피·원주) | 45초 |
| 문장제 | 50초 |

- 저학년(3~4학년) +5초 보정
- 시간 초과 = 현행 유지(오답 처리 + 풀이 힌트 표시)
- **근거**: 30초 고정은 3-1 덧셈에는 남고 6-1 겉넓이엔 모자람 → 시간 압박이 찍기를 유도해 학습을 방해. 유형별 시간은 "풀 수 있는데 늘어지는 것"만 자름.

## 3. [P0] 후반 밸런스 — "타워가 계속 필요한 게임"으로

### 3-1. 원인 (프로브 + 라이브 데이터)
- 정답 보상 `180+웨이브×10`골드 × 콤보 → 후반 골드 무한 → 타워 16기 풀업 후 **더 살 것이 없음**
- 마법사 오토어택 + 스펠이 웨이브와 무관하게 강해 후반에도 타워 없이 버텨짐
- 웨이브 HP 배율이 60웨이브 이후에도 선형+α라 DPS 인플레를 못 따라감

### 3-2. 개선안
1. **무한 스케일링 강화**: 웨이브 50+부터 HP 배율 지수항 추가(`×1.04^(w-50)`) — "언젠가는 반드시 뚫리는" 서바이벌 구조로. 점수 = 도달 웨이브가 실력 지표가 되게
2. **골드 싱크 신설**: 타워 레벨 캡 10 → **각성 시스템**(레벨 10 타워를 골드 대량 소모로 상위 티어 변신). 후반 골드가 계속 쓸 곳이 있게
3. **마법사 성장 캡**: 오토어택 DPS를 "총 타워 DPS의 25% 이하"로 상한 — 타워가 주력이 되도록
4. **웨이브 변이(모디파이어)**: 30웨이브+부터 웨이브마다 랜덤 1개 부여 — "물리 저항 +50%" "이속 +30%" "마법 면역" 등 → 단일 타워 조합 파훼, 몬스터 다양성 체감 상승 (기존 25종 재활용 — 신규 에셋 0)
5. **검증 게이트**: balance-probe에 판정 추가 — "95% 정답률 봇이 웨이브 60을 넘지 못할 것" + "60% 정답률이 웨이브 15+ 생존" 둘 다 통과해야 배포

> 몬스터 신규 제작은 불필요 판정: 25종+보스7은 충분. 부족한 건 **종류가 아니라 후반 조합 변주** → 4번으로 해결.

## 4. [P0] 전국 랭킹 — 일간 / 주간 / 월간

### 4-1. 스키마 변경
```sql
-- rankings에 컬럼 추가: week_key(예 2026-W30), month_key(예 2026-07)
-- 보존기간 7일 → 400일 (일·주·월 집계 모두 원본에서 조회)
-- 인덱스: (week_key, score DESC), (month_key, score DESC)
```
- 랭킹 화면 탭: **일간 | 주간 | 월간 | 명예의전당** × 학기 필터(현행 학년 필터 확장)
- 갱신 기준: 현행 KST 8:50 컷 유지(등교 직후 "어제의 왕" 발표 문화에 맞음), 주간=월요일 시작, 월간=달력 월

### 4-2. 치트 방어 (배포 전 필수)
1. **정합성 검사(서버)**: `score ≤ 웨이브별 이론 최대점수(wave)` 공식으로 상한 검증 — 웨이브 5에 100만점 등록 차단
2. **세션 토큰**: 게임 시작 시 발급한 난수 토큰을 제출 시 요구(+ 최소 플레이 시간 검증: 웨이브당 최소 20초)
3. **레이트 리밋**: IP당 제출 분당 3회 (CF Functions 내 D1 카운터)
4. 이름 필터: 욕설·교사 사칭 차단 목록(초등 배포 필수)

### 4-3. 읽기 최적화 (동접 대비 핵심)
- `/api/rankings` 응답을 **Cache API로 60초 캐싱** → D1 읽기가 트래픽과 무관하게 분당 ≤ 탭 수로 고정. 이거 하나로 읽기 병목 소멸

## 5. [P1] 학습 실효성 보강

- **오답노트 화면**: 세션 종료(게임오버/스테이지 클리어) 시 이번 판 틀린 문제 목록 + 풀이 힌트 복습 화면 → "게임은 재밌는데 뭘 배웠는지 모름" 방지. localStorage 저장, 다음 판 시작 전 3문항 복습 퀴즈(보너스 골드)
- 간격 반복 강화: 현행 3웨이브 뒤 1회 → **맞힐 때까지 3→7→15웨이브 간격 반복**
- 정답률 통계를 게임오버 화면에 표시(유형별 취약점 1줄: "분수 나눗셈에서 많이 틀렸어요")

## 6. [P1] 무한 즐길 거리 (리텐션)

- 스테이지 시스템(기존)과 무한 모드 병행: 120웨이브 이후에도 §3의 무한 스케일링으로 계속 — 기록 갱신형
- 일일 도전: "오늘의 시드"(전국 공통 웨이브 조성) — 같은 조건에서 순위 경쟁 → 일간 랭킹과 시너지

## 7. 동접 수용량 산정 (현 인프라, 무료 티어)

| 자원 | 무료 한도 | 게임의 소비 | 수용량 |
|---|---|---|---|
| CF Pages 정적 | 사실상 무제한 | 게임 본체·에셋(2.3MB) 전부 정적 | **동접 제한 없음** |
| Pages Functions | 10만 req/일 | 점수 제출 1 + 랭킹 조회 ~2/세션 | **~3만 세션/일** |
| D1 읽기 | 500만 row/일 | 캐싱(§4-3) 적용 시 미미 | 병목 아님 |
| D1 쓰기 | 10만/일 | 제출당 1~3 write | **~3만 제출/일** |

**결론: 게임플레이 자체는 100% 클라이언트라 동접 무제한. 병목은 점수 제출뿐이고 무료 티어로 일 3만 세션(≈전교생 단위 수십 개 학교 동시 사용) 커버.** 전국 확산 시 Workers 유료($5/월)로 1천만 req/일 — 코드 변경 없이 요금제만 전환.

추가 최적화(비용 0):
- 랭킹 캐싱(§4-3) — 최우선
- 에셋 `Cache-Control: immutable` 헤더(`_headers` 파일) — 재방문 로드 0
- 학기 분할로 문제 파일도 절반 크기(학기당 ~250KB)

**⚠️ 교사 배포 URL은 `https://mathcastle.pages.dev` 하나로 안내** (GitHub Pages 주소는 랭킹 미작동 — 리다이렉트 안내 페이지로 교체 예정)
