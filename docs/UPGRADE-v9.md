## 불변식 (교차검증자에게 전달하는 성공조건 — 3개)

1. **학습 → 결과 연결을 끊지 않는다.** `node tools/accuracy-sweep.mjs --gate` 통과 유지(정답률 60%↔90% 생존 차이 ≥8웨이브, 60~100% 단조). 신규 보상·축복은 **집중력 계수·각성 상한·정답 보상 계수·처치 골드 배율을 건드리지 않는다.**
2. **시간 축은 하나다.** v9에서 추가하는 모든 시간 기반 로직(연출 지속·히트스톱·쿨다운)은 `gameClock` 기준이다. `performance.now()`/`Date.now()`/게임 루프 밖 `setTimeout` 금지 — 배속과 일시정지가 자동 반영되어야 한다.
3. **아동 안전·접근성.** 색만으로 구분되는 정보 0(라벨·별 개수 동반), `prefers-reduced-motion`에서 화면 흔들림·플래시 차단, 압박형 스트릭·과금·개인정보 수집 0. CSP(`style-src 'self'`) 위반 0 — innerHTML의 `style=` 속성 금지, CSSOM(`el.style.setProperty`)만.

## A. 등급 가독성 — "좋은 건 보면 안다"

### 실측 진단
```
gameData.js:176  golden: { name:"황금 왕관", damage:125, range:165, cost:0, cooldown:600, splashRadius:65 }
ui.js:31         getTowerTier(key, stat) → cost 기준 + golden/silver/copper/ultimate/transcendent 하드코딩 예외
ui.js:202        if (towerStat.cost <= 0 && !towerStat.isRandom) continue;   ← 특수 타워는 메뉴에 없음
ui.js:560        `비용: ${data.cost}G`                                        ← 황금 왕관 툴팁이 "비용: 0G"
main.js:3216     showUpgradeNotification(`✨ ${name} 타워 획득! ✨`)          ← 전설도 기본도 같은 연출
```
황금 왕관은 DPS 208(125/0.6s)에 스플래시 65 — **전 타워 중 3위권**인데, 화면 어디에도 "이게 세다"는 신호가 없고 툴팁은 오히려 0G(=싸구려)라고 말한다.

### 처방
1. **`rarity.js` 신설 — 등급의 단일 진실원.** 비용이 아니라 **실효 전투력**으로 결정론 산출:
   `power = dps × splash계수 × range계수 × util계수` (dps = damage/cooldown 또는 dps 필드). 6등급 = 일반·고급·희귀·영웅·전설·초월. 하드코딩 예외 제거 — 타워를 추가해도 등급이 자동으로 붙는다.
   - 등급마다 `{ label, color, stars, key }`. **색+별 개수+한글 라벨을 항상 함께** 낸다(색각이상 대비).
2. **필드 표시.** `towerRenderer.render()` 뒤에 등급 링(색·두께)을 그린다. 전설·초월만 은은한 회전 오라(`gameClock` 위상). `quality.low`·reduced-motion에서는 링만.
3. **획득 연출 등급 차등**(랜덤 상자):
   - 일반~희귀: 현행 유지(조용)
   - 영웅: 파티클 burst + 등급 색 프레임
   - 전설·초월: 상자가 갈라지는 0.9초 개봉 + `screenFlash` 약 + `shockwave` + 전용 팡파레 + `★★★ 전설` 라벨
   - ⚠️ 현재 `setTimeout(…, 1000)`으로 열리는데 **게임 루프 밖이라 일시정지를 모른다**(메모리에 기록된 메테오 함정과 같은 계열). `gameClock` 기반 지연 큐로 교체한다.
4. **툴팁·업그레이드 패널**에 등급 배지 + `이 판 화력 순위 N/M`. 특수 타워 비용은 `0G` 대신 **`상자 전용`**.
5. **건설 메뉴** tier dot에 라벨 병기.

### 게이트 `tools/qa-rarity.mjs`
① 전 타워 등급 산출이 결정론적이고 하드코딩 예외 0 ② 전설 획득 시 개봉 연출이 관측(효과 제거를 주입하면 FAIL) ③ 등급 표시 요소에 라벨·별이 동반(색 단독 0) ④ 툴팁에 `0G` 표기 0건.

## B. 타격감 — "맞은 것 같지가 않다"

### 처방 (전부 `gameClock` 기준)
1. **히트 플래시** — 피격 시 `m._hitFlashUntil = gameClock + 90`, monsterRenderer가 흰색 합성. 비용 거의 0, 체감 최대.
2. **히트스톱** — 큰 타격(피해 ≥ 대상 최대체력 10% 또는 스플래시 명중)에 게임 시계 40~70ms 정지. **1초당 2회 상한**(연출이 게임을 느리게 만들면 안 된다).
3. **넉백** — 비보스 지상 몬스터를 경로 역방향 2~6px(피해 비례). `pathIndex` 좌표계에서 클램프 — 경로 이탈 불가.
4. **폭발 승격** — 스플래시 타워는 반경 비례 `shockwave` + 파편 8~16개. 미사일(`skyDestroyer`)은 전용 폭발(2단 링 + 화염 파편).
5. **카메라 흔들림** — 스플래시·보스 처치·성 피격에만. 진폭 상한 6px·200ms. 설정 토글 + reduced-motion 차단.
6. **사운드** — `hit` 피치 ±8% 랜덤(반복 피로↓), 큰 타격은 `explosion` 레이어 가산. 기존 쿨다운 유지.
7. **데미지 텍스트** — 피해량 비례 크기·굵기(등급 색). 밸런스 수치는 불변(치명타 도입 안 함).

⚠️ **성능 예산**: 프레임당 신규 파티클 상한, `quality.low`는 플래시·넉백만. qa-perf 회귀 금지.

### 게이트 `tools/qa-impact.mjs`
① 미사일 착탄 프레임에 flash·shockwave·파편이 관측(효과 제거 주입 시 FAIL) ② 히트스톱 1초 2회 상한 준수 ③ reduced-motion에서 흔들림 0 ④ `quality.low` 파티클 예산 이내 ⑤ 2배속에서 연출 지속이 벽시계 기준 절반(게임 시계 반영 확인).

### 답변 (사용자 질문)

## E. 일시정지·이어하기

### 실측 결함 4
1. 일시정지에 **오버레이가 없다** — 멈춘 건지 렉인지 아이가 모른다(`main.js:5274`는 버튼 글자만 교체).
2. **탭 전환 자동정지 없음.** `blur`(main.js:5132)는 눌린 키만 비운다. rAF는 멈춰도 `startSpawnLoop`의 `setInterval`은 계속 돈다 → 백그라운드에서 스폰이 쌓인다.
3. **웨이브 도중 저장 없음.** 오토세이브는 웨이브 완료 시 1회. `buildGameState()`에 monsters/projectiles가 없어 정확 복구도 불가.
4. 일시정지 중 **할 수 있는 게 없다** — 저장·설정·나가기가 다른 버튼에 흩어져 있다.

### 처방
1. **일시정지 오버레이 모달** — 웨이브·골드·성 체력 요약 + `계속하기` / `저장하고 나가기` / `설정` / `처음으로`. P·ESC 토글.
2. **자동 일시정지** — `visibilitychange(hidden)`·`pagehide`에서 정지 + 조용한 저장. **복귀 시 자동 재개 금지**(돌아오자마자 성이 깨지는 걸 막는다) — 오버레이를 띄운 채 기다린다.
3. **웨이브 중 이탈 정책 = 웨이브 시작 스냅샷.** `startWave()`에서 스냅샷을 남기고, 웨이브 진행 중의 저장 요청은 그 스냅샷을 기록한다. 몬스터를 저장하지 않으므로 불공정도 손실도 없다 — 그 웨이브를 처음부터 다시 한다. 문구도 그대로: `웨이브 12 시작 지점에 저장했어요`.
4. **세이브 버전 7** + v6→v7 자동 마이그레이션(무손실).
5. **이어하기 버튼에 내용 표기** — `4-1 · 웨이브 12 · 어제 저장`.

### 게이트 `tools/qa-pause-resume.mjs`
① P/ESC로 오버레이 표시·해제 ② 문서 숨김 시 `gamePaused=true` & 스폰 정지 ③ 웨이브 도중 저장 → 복구 시 웨이브 시작 상태와 골드·타워 일치 ④ v6 세이브 → v7 마이그레이션 무손실 ⑤ 오버레이가 열린 동안 `gameClock` 정지.

### R2. 히트스톱은 게임 시계를 **멈추지 않는다** (종료조건 성립 불가)
- codex 지적, 코드 확인. rev1의 `hitStopUntil = gameClock + 70`은 gameClock을 멈추는 순간 그 시각에 **영원히 도달하지 못한다**(main.js:1875 `gameClock += deltaTime`).
- **개정**: `hitstopRemainingMs`(실시간 누산기)를 두고 `gameLoop`의 `!gamePaused` 블록 안에서 `rawDeltaTime`으로 감산한다. 히트스톱 동안엔 `deltaTime *= 0.08`로 **시뮬 전체를 느리게** 흘린다(gameClock 포함) — 교착 없음, 배속과 무관하게 체감 지속이 동일, 일시정지 중엔 누산 자체가 안 된다.
- **딸린 개정 — 스포너를 게임 시계 구동으로 교체.** 현재 스폰은 `setInterval`(main.js:2994)이라 게임 시계와 분리돼 있다. 히트스톱으로 게임 시간이 느려지면 스폰만 벽시계로 앞서 나가 웨이브 밀도가 왜곡된다. `nextSpawnAt`을 gameClock으로 두고 게임 루프에서 판정하도록 바꾼다. 부수 효과로 기록된 결함(배속 토글 시 인터벌이 옛 비율로 남던 문제)과 탭 백그라운드 스폰이 함께 사라진다.
- 예산 기준도 명시: **실시간 1초당 최대 2회 · 회당 최대 45ms**.

### R3. 넉백 단위 — `pathIndex`는 픽셀이 아니다
- codex 지적, 코드 확인. `main.js:4105`에 `Math.floor(spell.pushbackPx / 5); // pathPoints는 5px 간격`, `main.js:2582`도 `teleportDistance / 5`. rev1의 "pathIndex에서 2~6px를 뺀다"는 실제로 **10~30px 밀림**이 된다.

### R4. `prefers-reduced-motion` 배선이 **아예 없다** — 신규만 막으면 거짓 통과
- 3계열 전부 지적. 코드 확인: JS `matchMedia` 호출 0건, CSS는 `style.css:3530`의 `.rotate-phone` 하나뿐. 반면 성 피격 흔들림(`main.js:2663-2664`)과 `screenFlash` 호출 10곳 이상이 **이미 무가드**다.
- **개정**: `a11y.js` 신설 — `prefersReducedMotion()` + `change` 리스너(OS 설정 실시간 반영). 신규 효과뿐 아니라 **기존 흔들림·강한 플래시도 이번에 함께 게이팅**한다. 게이트는 신규·기존을 모두 스캔한다.
- 광과민성(PSE): 화면 전체 플래시는 **실시간 1초에 최대 2회**로 제한(기준 3회 미만). 몬스터 히트 플래시는 개체 국소라 전면 플래시로 세지 않되, 개체당 최소 간격 120ms를 둔다.

### R5. 일시정지 오버레이에 `.modal` 클래스를 쓰면 **P키가 죽는다**

### R7. "웨이브 시작 스냅샷"은 **무한 재추첨 구멍**이다 → 중간 상태를 통째로 저장한다

2. **새로 스폰된 몬스터를 "복원된 몬스터"로 오인했다.** "몬스터 수 > 0"은 중간 상태를
   버려도 통과한다(스포너가 새로 채우니까) → 저장 시점의 **선두 경로 위치**와 대조한다.
3. **연출 유무로 사건을 셌다.** qa-meteor-pause가 `.magic-attack` DOM 노드로 낙하를
   판정했는데, 저사양 강등 시 `createMagicEffect`가 DOM을 **정상적으로** 건너뛴다
   (캔버스만 그린다) → 부하가 걸린 전체 스위트에서만 "회귀"로 오판됐다.
   착탄 자체를 세는 훅으로 교체했다. 🔴 **일반 교훈: 연출은 사건의 증거가 아니다.**

## qa-projectiles 게이트를 더 엄격하게 고쳤다

런타임 관측 발사체 종류가 실행마다 2~7종으로 요동쳤다(v9 이전에도 4~5종). 원인은
초강력 타워(궁극·전설·특수)가 몬스터를 **먼저 다 지워서** 나머지 타워가 표적을 못 잡는

## 밸런스 시뮬의 한계 — 정직하게 남긴다

축복을 `tools/accuracy-sweep.mjs`에 최악 선택(봇이 항상 화력 우선 선택)으로 모델링했고

| 올리면 뭐가 좋아지는가 | **레벨 하나가 새 마법 하나를 연다** — Lv2 서리 고리, Lv3 연쇄 번개 … Lv10 대마법: 심판 |
| 지금 살 수 있는가 | 못 사면 `disabled`로 흐려질 뿐, 살 수 있게 된 순간에 아무 신호도 없었다 |

가장 큰 손실은 두 번째다. **레벨업이 곧 새 마법 해금인데 그 인과가 어디에도 없었다.**

## 조치 (밸런스 무변경 — 비용도 효과도 그대로, 보이게만 한다)

1. **버튼에 비용 상시 표기** — `⬆️ 150`. 못 살 때야말로 "얼마를 모으면 되는지"가 필요하다.
2. **살 수 있게 되면 초록 맥박** — `.affordable` 클래스. 항상 번쩍이면 그냥 배경이 되므로
   **살 수 있을 때만**. `prefers-reduced-motion`에서는 색만 남기고 맥박은 끈다.
3. **툴팁에 다음 해금 마법** — 「마법사 Lv.2 — 150골드 · 새 마법 「서리 고리」가 열려요」.
   `aria-label`도 같이 세운다.
4. **처음 살 수 있게 된 순간 1회 안내** — 매번 띄우면 잔소리, 안 띄우면 지금까지처럼 아무도 모른다.
   레벨이 오르면 다시 무장하고, 판이 바뀌면 초기화한다.

## 🔤 한글 조사 — 두 번 틀렸다

처음 문구가 **"「서리 고리」이 열려요"**로 나왔다. 받침 유무로 이/가를 갈라야 한다.
그래서 `particleFor()`를 만들었는데, **판정 대상을 「」까지 포함한 문자열로 줬다.**
마지막 글자가 한글이 아니라 9종이 **전부 "가"**로 찍혔다(실측) — 절반이 틀린 상태로
"고쳤다"가 될 뻔했다.

> **교훈: 조사 판정은 낱말 자체로 한다. 장식(괄호·따옴표·이모지)을 씌운 채로 재면
> 마지막 글자가 한글이 아니게 되어 늘 같은 답이 나오고, 그게 절반은 맞기 때문에
> 눈으로는 통과해 버린다.**

게이트에 마법 이름 9종 전수 조사 검사를 넣었다(`qaNextSpellAtLevel`·`qaParticleFor`).
